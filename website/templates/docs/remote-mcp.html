Remote MCP Setup

Expose your local tuiml-mcp server to agents running elsewhere — on your own infrastructure.

Read this first

  • TuiML does not host or proxy MCP traffic. Everything below runs on your infrastructure.
  • tuiml-mcp ships with stdio transport only. To go remote you'll either expose stdio via a bridge or wrap it behind your own HTTP/SSE adapter.
  • You must add authentication. An unauthenticated MCP server lets anyone train models, read files, and execute Python on your machine.
  • If you only need tuiml on multiple machines, the simpler answer is uv tool install tuiml on each one — no tunnel required.

When you actually need remote MCP

Local stdio is the right answer for almost every TuiML use. Reach for remote only when:

  • You want an agent running in the cloud (a hosted ChatGPT/Claude app, a CI runner, a teammate's laptop) to call your TuiML install and its trained models.
  • You're building a shared MCP gateway for a team and want one TuiML instance backing everyone.
  • You need to keep large datasets on one machine and have lightweight clients elsewhere.

If none of those apply, use the local install instead.

Option A — Cloudflare Tunnel recommended

Free, stable subdomain, no rate limits, supports authentication via Cloudflare Access. Best fit if you already own a domain.

  1. Install cloudflared: brew install cloudflared (macOS) or follow Cloudflare's docs.
  2. Authenticate and create a tunnel: 
    cloudflared tunnel login
cloudflared tunnel create tuiml-mcp
  3. Run an MCP-over-HTTP bridge in front of tuiml-mcp (see Bridging stdio → HTTP below).
  4. Point the tunnel at the bridge port: 
    cloudflared tunnel route dns tuiml-mcp mcp.example.com
cloudflared tunnel run --url http://localhost:8765 tuiml-mcp
  5. Enable Cloudflare Access on the hostname for SSO / token auth.

Option B — ngrok

Fastest to try. Free tier rotates the URL on every restart; paid tier gives you a static subdomain. Add an auth token or your MCP endpoint is publicly callable.

# Start your HTTP bridge first (see below)
ngrok http 8765 --basic-auth="tuiml:<your-strong-token>"

Paste the resulting https://<hash>.ngrok-free.app URL into each MCP client's config. Note: the URL changes every restart on the free plan.

Option C — Tailscale (private network)

Best when both the agent and the TuiML host are your devices. No public exposure — traffic is end-to-end encrypted over Tailscale's mesh.

# Install tailscale on both ends, then on the TuiML host:
tailscale serve --bg --https=8443 http://localhost:8765
# The MCP URL is then https://<host>.<tailnet>.ts.net:8443

Tailscale handles identity for you — no need to bolt on basic-auth.

Option D — Your own VPS + reverse proxy

For team / production use. Run the HTTP bridge on a VPS (DigitalOcean, Hetzner, etc.), terminate TLS with nginx + Let's Encrypt, and require a bearer token on every request.

server {
  listen 443 ssl http2;
  server_name mcp.example.com;

  # ssl_certificate ...; (managed by certbot)

  location / {
    if ($http_authorization != "Bearer <your-shared-secret>") { return 401; }
    proxy_pass         http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header   Connection "";
    proxy_buffering    off;
  }
}

Bridging stdio → HTTP / SSE

Because tuiml-mcp speaks stdio, you need a small bridge that translates SSE/HTTP MCP messages into stdin/stdout for the child process. Two open-source options:

  • mcp-proxy — single binary, exposes stdio servers over SSE. 
    mcp-proxy --sse-port 8765 -- tuiml-mcp
  • MCP Inspector — useful for local debugging, also speaks SSE.
  • Roll your own with the MCP Python SDK's SseServerTransport.

A native HTTP transport may land in a future TuiML release; for now the bridge approach is the most portable.

Wiring a remote URL into your AI client

Whichever option you chose, the client config replaces the local command entry with a url entry (exact key depends on the client). Example for a Claude-Desktop-style JSON config:

{
  "mcpServers": {
    "tuiml-remote": {
      "url": "https://mcp.example.com/sse",
      "headers": { "Authorization": "Bearer <your-shared-secret>" }
    }
  }
}

Restart the client after editing the config.

Security checklist

  • Require authentication on every public endpoint. Bearer tokens, mTLS, Cloudflare Access, or Tailscale identity — pick one and enforce it.
  • Bind the bridge to 127.0.0.1 and let the reverse proxy / tunnel handle the public surface. Never bind 0.0.0.0 on an internet-facing host.
  • Keep $TUIML_ALLOW_USER_ALGORITHMS unset on a remote host unless you fully trust every caller — that flag lets agents write and execute Python.
  • Use a dedicated unix user / container for the MCP process so file-system access is scoped.
  • Log every request at the proxy layer (IP, time, route) so you can audit usage later.
