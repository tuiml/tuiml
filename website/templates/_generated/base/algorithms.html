Base classes and registration decorators for machine learning algorithms.

This module provides the foundation for the plugin-based algorithm system. All base classes (Classifier, Clusterer, Regressor, Associator) are defined here and integrate with the component registry (tuiml.registry).

class base.algorithms.Algorithm(Registrable, ABC)

Abstract base class for all machine learning algorithms.

Provides a unified interface for model lifecycle management, including training, prediction, evaluation, persistence, REST serving, and registration with the component registry.

This class serves as the foundation for the specialized base classes such as Classifier and Regressor. It defines standard methods for metadata retrieval, parameter handling, and REST serving.

AssociationRule

class base.algorithms.AssociationRule

Represents a discovered relationship in the form $A \Rightarrow C$.

Overview

Association rules quantify how likely the consequent ($C$) is to appear given the presence of the antecedent ($A$).

Parameters

antecedent
frozenset of int
The conditional part of the rule ($A$).
consequent
frozenset of int
The predicted part of the rule ($C$).
support
float
The joint probability: :math:`P(A \cup C)`.
confidence
float
The conditional probability: :math:`P(C|A) = \frac{P(A \cup C)}{P(A)}`.
lift
float = 1.0
The ratio of observed support to expected support if independent: :math:`\frac{P(C|A)}{P(C)}`.
leverage
float = 0.0
The difference from independence: :math:`P(A \cup C) - P(A)P(C)`.
conviction
float = 1.0
Implication strength: :math:`\frac{1 - P(C)}{1 - \text{confidence}}`.
jaccard
float = 0.0
Jaccard coefficient: :math:`\frac{P(A \cup C)}{P(A) + P(C) - P(A \cup C)}`.
kulczynski
float = 0.0
Average of the two conditional confidences :math:`P(C|A)` and :math:`P(A|C)`.
all_confidence
float = 0.0
Minimum of the two conditional confidences.

Methods

__repr__ (self) -> str

Return a string representation showing the rule and its metrics.

call_metric(metric_func, y_true, y_pred)

Call a metric function, choosing macro averaging for multiclass data.

TuiML's f1_score/precision_score/recall_score default to binary averaging, which on multiclass labels silently reports only the score of class 1. Whenever the metric accepts an average argument and the data has more than two classes, macro averaging is used instead.
