{{ config.project_name }} is open source and designed to be extensible. Whether you want to add a new algorithm, fix a bug, or improve documentation, this guide covers everything you need.

Design philosophy: native implementations first

{{ config.project_name }} ships its own implementations — with C++ hot paths for performance-critical code — rather than wrapping other libraries. That is what makes it a library rather than a facade, and it is the single most important thing to understand before you write code.

Bridges to external libraries are welcome, but they live in their own dedicated packages — tuiml.sklearn and tuiml.capymoa — as optional extras, never inside the core namespaces. See External Libraries for the full rules.

Algorithm Structure

A complete example of a nearest-centroid classifier implementation.

PYTHON 
"""My Custom Classifier implementation."""

import numpy as np
from typing import Dict, List, Any, Optional

from tuiml.base.algorithms import Classifier, classifier


@classifier(tags=["custom", "example"], version="1.0.0")
class MyCustomClassifier(Classifier):
    """A custom classifier for demonstration purposes.

    This is a simple nearest-centroid classifier that assigns each sample
    to the class of the nearest cluster centroid.

    Parameters
    ----------
    metric : str, default="euclidean"
        Distance metric to use for computing distances to centroids.
        Options: "euclidean", "manhattan"

    Attributes
    ----------
    classes_ : np.ndarray
        Unique class labels.
    centroids_ : np.ndarray
        Centroid for each class, shape (n_classes, n_features).
    """

    def __init__(self, metric: str = "euclidean"):
        super().__init__()
        self.metric = metric
        self.classes_ = None
        self.centroids_ = None

    @classmethod
    def get_parameter_schema(cls) -> Dict[str, Dict[str, Any]]:
        """Return JSON schema for parameters."""
        return {
            "metric": {
                "type": "string",
                "default": "euclidean",
                "enum": ["euclidean", "manhattan"],
                "description": "Distance metric for centroid computation"
            }
        }

    @classmethod
    def get_capabilities(cls) -> List[str]:
        """Return supported data capabilities."""
        return ["numeric", "binary_class", "multiclass"]

    def fit(self, X: np.ndarray, y: np.ndarray) -> "MyCustomClassifier":
        """Fit the classifier to training data."""
        X = np.asarray(X, dtype=float)
        y = np.asarray(y)

        if X.ndim == 1:
            X = X.reshape(-1, 1)

        self.classes_ = np.unique(y)
        self.centroids_ = np.array([
            X[y == c].mean(axis=0) for c in self.classes_
        ])

        self._is_fitted = True
        return self

    def predict(self, X: np.ndarray) -> np.ndarray:
        """Predict class labels for samples."""
        self._check_is_fitted()
        X = np.asarray(X, dtype=float)

        if X.ndim == 1:
            X = X.reshape(-1, 1)

        distances = np.sqrt(
            np.sum((X[:, np.newaxis, :] - self.centroids_) ** 2, axis=2)
        )
        return self.classes_[np.argmin(distances, axis=1)]

1

Choose the Right Location

Place your algorithm in the appropriate subdirectory under tuiml/algorithms/:

bayesian/

Probabilistic models

Decision trees & forests

linear/

Linear models

neural/

Neural networks

ensemble/

Meta-learners

clustering/

Clustering algorithms

2

Create Your Algorithm File

Create a new Python file with a descriptive name (e.g., my_algorithm.py).

Naming conventions: lowercase with underscores, be descriptive (e.g., gradient_boosting_classifier.py), avoid abbreviations unless standard (e.g., svm.py).
3

Implement the Algorithm

Follow the structure shown above. Your checklist:

  • Inherit from the correct base class
  • Use the appropriate decorator (@classifier, @regressor, etc.)
  • Implement fit() and predict() methods
  • Set self._is_fitted = True at the end of fit
  • Implement metadata methods for hub integration
4

Export from __init__.py

Update both the category and main __init__.py files to export your class:

PYTHON 
# tuiml/algorithms/your_category/__init__.py
from .my_algorithm import MyCustomClassifier

__all__ = [
    # ... existing exports ...
    "MyCustomClassifier",
]

# tuiml/algorithms/__init__.py
from tuiml.algorithms.your_category import MyCustomClassifier
5

Write Tests and Submit

Add a test file in tests/, verify all tests pass with uv run pytest, then open a pull request.

External Libraries

{{ config.project_name }} has bridges to scikit-learn and CapyMOA, and we welcome contributions that extend them. But where that code lives is not a matter of taste — it is the rule that keeps the core library coherent.

The one rule

Never put wrapper files inside the core namespaces. A file named sklearn_rf.py does not belong in tuiml/algorithms/trees/. The core algorithms/, preprocessing/, and features/ packages contain native {{ config.project_name }} implementations only. Wrappers go in tuiml/sklearn/ or tuiml/capymoa/. Mixing them makes the library look like a thin shell over scikit-learn and leaves users unable to tell what is actually ours.

Where does my contribution go?

What you are adding Where it goes Dependency
An algorithm implemented from scratch tuiml/algorithms/<family>/ core — no new deps
A scikit-learn estimator exposed to {{ config.project_name }} tuiml/sklearn/ tuiml[sklearn] extra
A CapyMOA streaming learner tuiml/capymoa/ tuiml[capymoa] extra
A bridge to some other library (JAX, PyTorch, cuML…) a new tuiml/<library>/ package its own extra

Name the package after the library it wraps (sklearn, capymoa) — not after the capability it provides (streaming). Capability names are reserved for native {{ config.project_name }} implementations, so tuiml/algorithms/streaming/ stays free for streaming algorithms we write ourselves.

Why wrappers never collide with native algorithms

Each bridge registers into the hub under a namespaced key — sklearn.<ClassName> or capymoa.<ClassName>. That is what lets a scikit-learn RandomForestClassifier and a native {{ config.project_name }} RandomForestClassifier coexist, and it lets users choose between them explicitly:

PYTHON 
from tuiml.algorithms import RandomForestClassifier          # native TuiML
from tuiml.sklearn    import RandomForestClassifier as SkRF   # sklearn-backed

# ...or by hub key, which is what agents and the CLI use:
tuiml.train("RandomForestClassifier", data)           # native
tuiml.train("sklearn.RandomForestClassifier", data)   # sklearn

# Any scikit-learn estimator is auto-wrapped — no curated class needed:
from sklearn.svm import SVC
tuiml.train(SVC(), data)

Adding a curated wrapper

A wrapper declares its constructor parameters and builds the backing estimator lazily. The _build_estimator() method is the only place the external library is ever imported — that is what keeps the dependency optional:

tuiml/sklearn/algorithms.py 
from tuiml.base.algorithms import Classifier
from tuiml.sklearn._base import _SklearnBackedMixin, sk_classifier


@sk_classifier(tags=["ensemble", "tree"])
class RandomForestClassifier(_SklearnBackedMixin, Classifier):
    """scikit-learn RandomForestClassifier (hub key ``sklearn.RandomForestClassifier``)."""

    def __init__(self, n_estimators: int = 100, random_state: int | None = None):
        super().__init__()
        self.n_estimators = n_estimators
        self.random_state = random_state

    def _build_estimator(self):
        # The ONLY import of sklearn — lazy, so `import tuiml` never needs it.
        from sklearn.ensemble import RandomForestClassifier as _Est
        return _Est(n_estimators=self.n_estimators, random_state=self.random_state)

    @classmethod
    def get_parameter_schema(cls) -> dict:
        return {"n_estimators": {"type": "integer", "default": 100}}

    @classmethod
    def get_capabilities(cls) -> list:
        return ["numeric", "multiclass", "probabilities"]

You never write the fit / predict bridge yourself — the mixin does it, and it raises a clear ImportError pointing at pip install 'tuiml[sklearn]' if the library is missing. CapyMOA works the same way via tuiml/capymoa/_base.py, adapting its instance-at-a-time API to {{ config.project_name }}'s batch interface.

Do

  • Keep every wrapper inside tuiml/sklearn/ or tuiml/capymoa/
  • Import the external library lazily, inside _build_estimator()
  • Register the dependency as an extra in pyproject.toml
  • Prefer a native implementation when the algorithm is core to the library

Don't

  • Add sklearn_*.py files to algorithms/, preprocessing/, or features/
  • Import sklearn or capymoa at module top level
  • Make a native algorithm depend on an external library
  • Use sklearn for splitting or metrics — {{ config.project_name }} has evaluation.splitting and evaluation.metrics

Testing Your Algorithm

Writing tests ensures your algorithm works correctly. {{ config.project_name }} uses pytest.

PYTHON 
# tests/algorithms/your_category/test_my_algorithm.py

import numpy as np
import pytest
from tuiml.algorithms.your_category import MyCustomClassifier


class TestMyCustomClassifier:
    """Test suite for MyCustomClassifier."""

    def test_initialization(self):
        """Test that classifier initializes correctly."""
        clf = MyCustomClassifier(metric="euclidean")
        assert clf.metric == "euclidean"
        assert not clf._is_fitted

    def test_fit(self):
        """Test fitting on simple data."""
        X = np.array([[1, 2], [2, 3], [3, 4], [6, 7], [7, 8]])
        y = np.array([0, 0, 0, 1, 1])

        clf = MyCustomClassifier()
        clf.fit(X, y)

        assert clf._is_fitted
        assert hasattr(clf, 'classes_')
        assert len(clf.classes_) == 2

    def test_predict(self):
        """Test predictions."""
        X_train = np.array([[1, 2], [2, 3], [3, 4], [6, 7], [7, 8]])
        y_train = np.array([0, 0, 0, 1, 1])
        X_test = np.array([[1.5, 2.5], [6.5, 7.5]])

        clf = MyCustomClassifier()
        clf.fit(X_train, y_train)
        predictions = clf.predict(X_test)

        assert len(predictions) == 2
        assert predictions[0] == 0
        assert predictions[1] == 1

    def test_parameter_schema(self):
        """Test that parameter schema is returned."""
        schema = MyCustomClassifier.get_parameter_schema()
        assert "metric" in schema

Documentation Convention

{{ config.project_name }} uses NumPy/SciPy docstring style. Reference: algorithms/anomaly/isolation_forest.py.

Never use Google style (Args: / Parameters:). Headers must use dash underlines: Parameters\n----------

Algorithm Docstring Sections

1 Summary
2 Overview
3 Theory
4 Params
5 Attrs
6 Notes
7 Refs
8 See Also
9 Examples

For datasets/ and features/ folders, keep docs short: Summary + Parameters + Returns only.

Math Notation

Use RST math (renders via KaTeX). Inline: :math:`x^2`. Display block: .. math::

LaTeX Backslash Rules

Python interprets \t \a \b \f \n \r \v as escape sequences in docstrings, mangling LaTeX. Use \\ for affected commands.

Must Double-Escape

\\text \\alpha \\beta \\frac \\begin \\nabla \\right \\varepsilon

Safe Single-Backslash

\sigma \sum \sqrt \lambda \log \pi \mu \infty

Quick Reference

Run uv run generate_docs.py after docstring changes to regenerate HTML
See Also: :class:`~tuiml.algorithms.svm.SMOReg` : Description.
References: [AuthorYear] format with DOI links
Timeseries models use Regressor base, not Classifier
Fitted attributes use trailing _ (scikit-learn convention)

Best Practices

Do

  • Handle missing values (NaN) gracefully
  • Validate input shapes and types
  • Write comprehensive NumPy docstrings
  • Include usage examples in docstrings
  • Set self._is_fitted in fit()
  • Use type hints for all methods
  • Follow PEP 8 style guidelines

Don't

  • Modify input arrays in-place
  • Rely on global state
  • Print to stdout (use logging)
  • Skip parameter validation
  • Return unexpected array shapes
  • Forget to call super().__init__()
  • Ignore edge cases (empty data, etc.)
